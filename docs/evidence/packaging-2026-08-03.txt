exit 1. This is a structural limit of BuildPlugin in 4.27, read from the engine
rather than guessed at:

  BuildPluginCommand.Automation.cs:129  CreateHostProject writes the host
      descriptor as a literal string enabling exactly one plugin, with no
      AdditionalPluginDirectories field.
  BuildPluginCommand.Automation.cs:133  and copies only that one plugin's
      directory into HostProject/Plugins.
  BuildPluginCommand.Automation.cs:66-69 wipes the package directory before
      any of that, so the dependency cannot be staged in beforehand.
  UEBuildTarget.cs:3229                 is where UBT then throws, because the
      reference is not optional.

No BuildPlugin argument fixes this. The dependency would have to be installed
into Engine/Plugins, which changes a shared engine install, or the plugin built
in a host project that has both. Section 4 is the second option.

4a. -NoHotReload is required, and the first attempt proved it
------------------------------------------------------------

The same build without -NoHotReload fails:

  [73/78] UE4Editor-JsEnv.dll
  LINK : fatal error LNK1181: cannot open input file
  'D:\...\Plugins\Puerts\Intermediate\Build\Win64\UE4Editor\Development\ParamDefaultValueMetas\UE4Editor-ParamDefaultValueMetas.lib'
  BUILD_EXIT=6

with no editor process running. UBT names ParamDefaultValueMetas with a
hot-reload suffix and JsEnv links against the unsuffixed import library. This is
an invocation defect, not a package defect: Scripts/bridge-install.mjs
buildTarget already passes -NoHotReload. It is now in README_INSTALL.txt,
because a recipient building by hand will hit it.

5. Manifest upgrade path
------------------------

Run against BridgePackageTest with a hand-written manifest, all three cases.
The first one crashed before this session:

  bridge install: Cannot read properties of undefined (reading 'slice')

checkInstall gates every manifest field read on schema trust, but the CLI
printer read manifest.bridge_commit unconditionally. A pre-versioning manifest
has no such field, so the process died before printing the refusal that
docs/RELEASE.md quoted. Fixed in Scripts/bridge-install.mjs; all three now
print:

  FAIL  manifest_schema: MCPBridgeInstall.json in ... has no integer schema_version,
        so it was written before the manifest was versioned. Its fields are not
        read. Re-run npm run install:sync -- --project <path> to rewrite it.

  FAIL  manifest_schema: ... is schema version 0; this checkout writes 1. Re-run
        npm run install:sync -- --project <path>, which rewrites the manifest at
        the current version.

  FAIL  manifest_schema: ... is schema version 2, which is NEWER than the 1 this
        checkout understands. The target was installed from a newer bridge
        checkout; syncing from here would move it backwards. Update this checkout
        instead.

The summary line under those said "run npm run install:sync" in every case,
including the third, which contradicted its own refusal on the one path where
syncing moves a target backwards. It now says each FAIL names its fix.
