# UE4.27 bridge gap audit

Measured 2026-07-29 against a live editor. Every number here comes from the built
server, the listener's route table, and the Python sources, not from documentation.

Headline: **146 tools advertised, 169 listener routes, 141 commands sent.**
Nothing is falsely advertised, no handler is a stub, and there are no duplicates.
The gaps are all of one kind: **capability that exists and works but cannot be
reached.**

## Clean results

| Check | Result |
|---|---|
| Tools sending a command with no route | none |
| Routed handlers that are stubs | none |
| Duplicate or overlapping tools | none |
| Tools missing annotations | none |
| Tools missing an input schema | none |

## Finding 1: 28 optimization routes are unreachable (highest value)

`handlers/optimization.py` is **2,536 lines and 24 working handlers**. None of them
has a TypeScript tool, so no MCP client can call any of it. They are allowlisted in
`registry-consistency.test.ts` under `INTERNAL_ONLY_PREFIXES = ["optimization_"]`
with the note "panel-driven internal suites (no MCP schema yet)", so the test
passes and the gap stays invisible.

This is not scaffolding. `optimization_tool_catalog` was called live during this
audit and returned a 15-entry catalog of UE4.27 profiling commands, each with a
category, the question it answers, when to use it, what a bad reading looks like,
and what to do next.

The stated capability area "Performance analysis, optimization, cloth" currently
resolves to **4 cloth tools out of a possible 32**.

What is dark:

| Group | Commands |
|---|---|
| Triage | quick_triage, tool_catalog, run_console_checklist, stat_capture |
| GPU | gpu_capture, profilegpu_capture, rendering_capture, viewmode_capture_set |
| CPU | cpu_capture, insights_trace_start/stop/summary, camera_path_profile |
| Memory | memory_streaming_capture |
| Audits | asset_audit, scene_audit, vr_audit, texture_harm_rank, asset_cost_rank |
| Fixes | fix_candidates, apply_low_risk_fixes, before_after_verify |
| Reporting | generate_report, visual_logger_ingest |

Exposing these is cheap: the Python is written, routed, and working. It needs
TypeScript definitions with accurate schemas and annotations. Two of them mutate
assets (`apply_low_risk_fixes`, `before_after_verify` with `apply_candidates`) and
need care; the rest read or capture.

## Finding 2: four panel-only bridge routes

`bridge_status`, `bridge_latest_notification`, `bridge_copy_project_info` and
`bridge_self_test` are routed but have no tool. Three are genuinely panel-only.
`bridge_self_test` is the arguable one: a client-callable self-test would be
useful, and it overlaps `npm run smoke`.

## Finding 3: thin areas measured against the stated surface

| Area | Tools | Notable absences |
|---|---|---|
| Levels, streaming, maps, World Outliner | 4 | no streaming-level or sublevel operations, no World Settings access |
| Materials, instances, textures | 6 | **no texture tools at all**, though textures are named in the target surface |
| Animation, AnimBP, montages, poses | 6 | **no montage tools**, though montages are named in the target surface |
| Widget Blueprints | 4 | builder is design-complete, implementation not started |
| Behaviour Trees, AI, navigation | 4 | creation only; no inspection or mutation of an existing tree from MCP |
| Audio, data assets, data tables | 4 | audio is one component-add tool |

Compare Blueprint (25 tools) and viewport/input/effects (21). The imbalance is
historical, not designed.

## Finding 4: no tool reference exists

**127 of 146 tool names appear nowhere in `AGENTS.md` or `README.md`.** Those
documents describe architecture and module names, which is correct for their
purpose, but there is no generated tool reference anywhere. A reader cannot answer
"what can this thing do" without starting the server.

This is the "documentation matches measured counts" gate, unmet.

## Finding 5: 17 thin tool descriptions

Under 60 characters, e.g. `redo` ("Redo previously undone operations."), `ue_logs`
("Fetch recent UE4 log entries."). Descriptions are the only thing a model uses to
choose a tool. These are the ones most likely to be picked wrongly or skipped.

15 tools take no parameters. Mostly correct (`test_connection`, `project_info`),
not treated as a defect.

## Priority

1. **Expose the optimization suite.** 24 working handlers, one whole stated
   capability area currently at 12 percent. Cheapest large win available.
2. **Generate a tool reference** from the live server so it cannot drift.
3. **Fill the named-but-absent gaps**: textures, montages, streaming levels.
4. **Rewrite the 17 thin descriptions.**
5. **Decide on `bridge_self_test`**: expose it or document why it is panel-only.

## Method

`node scripts/gap-audit.mjs` equivalent: start the built server over stdio, take
`tools/list`, parse `COMMAND_ROUTES` from `router.py`, parse every
`sendCommand(...)` literal from `mcp-server/src`, and cross-reference. Re-run it
after any tool change; every finding above is reproducible.
